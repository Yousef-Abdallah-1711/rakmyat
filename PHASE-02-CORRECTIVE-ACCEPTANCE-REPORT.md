## 4. Font loading: implementation deviation and measured payload

P02-T003/T004 acceptance criteria are phrased as locale-scoped loads and payload budgets. Those criteria pass. Their task objectives separately directed `next/font`; the implementation instead uses licensed self-hosted WOFF2 subsets, CSS `@font-face`, and conditional server-rendered `ReactDOM.preload` in `app/[locale]/layout.tsx`. The implementation report explains that the shared dynamic locale root produced English preload hints on Arabic routes with the former approach. This is a disclosed implementation deviation, not a change to the acceptance criteria. The original independent measurement is preserved below and in the unchanged audit.

| Locale | Actual observed font response bodies | Body bytes | Browser transferred bytes | Budget | Result |
|---|---|---:|---:|---:|---|
| English | Space Grotesk Latin, Inter Latin, IBM Plex Mono 400 | 80,804 | 81,704 | 180 KiB = 184,320 bytes | PASS |
| Arabic | IBM Plex Sans Arabic Latin + Arabic subsets | 47,456 | 48,056 | 120 KiB = 122,880 bytes | PASS |

Values are browser network response measurements, not filename estimates. English routes request no Arabic font files; Arabic routes request no English display/body faces and emit zero font preloads. `document.fonts.check` passes and Chromium platform-font inspection identifies IBM Plex Sans Arabic for Arabic heading glyphs. The Latin subset on Arabic routes covers Latin strings/branding and is not the Arabic glyph fallback. Fonts remain `font-display: swap` without metric-adjusted fallback. The prior delayed response run measured Arabic tablet CLS 0.0547 (English maximum 0.0013); this risk remains open for later headline-heavy typography review.
